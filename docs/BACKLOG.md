# 나중에 할 일

결정은 했지만 아직 만들지 않은 기능. 시작할 때 이 문서를 먼저 보고, 끝나면 지운다.

## 알림: 카카오 알림톡·문자(SMS)

지금은 이메일만 보낸다 (`notification/OrderNotifier`). 고객은 메일을 잘 안 보므로 오픈 후 알림톡·문자를 붙인다.

- **보낼 것**: 지금 메일과 같은 시점
  - 고객: 무통장 주문 접수(입금 계좌·금액·기한), 입금 확인, 발송(송장번호), 입금 기한 임박(선택)
  - 운영자: 새 무통장 주문 (운영자는 메일로 충분하면 생략)
- **준비물 (사용자)**
  - 발송 대행 가입: 솔라피, NHN Cloud Notification, 알리고 등 (건당 알림톡 약 8~15원, 문자 약 10~20원)
  - 문자: 발신번호 사전 등록 (통신사 서류 인증)
  - 알림톡: 카카오톡 채널 개설 → 발송 대행사에 채널 연결 → **템플릿마다 카카오 심사** (영업일 1~3일). 변수는 `#{주문번호}` 형태
  - 알림톡 실패 시 문자로 대체 발송(대행사 기능) 설정
- **구현 메모**
  - `Mailer`처럼 `KakaoSender`/`SmsSender`를 두고, 키가 없으면 발송 생략 (`MAIL_HOST`와 같은 방식)
  - `OrderNotifier`의 각 이벤트에서 메일과 함께 보낸다. 받는 번호는 주문의 받는 분 연락처(`receiver_phone_enc`, 복호화 필요)
  - 발송 결과(성공·실패·대체문자)를 기록할 테이블을 두면 고객 문의 대응이 쉽다
  - 마케팅성 문구는 넣지 않는다 (알림톡은 정보성 메시지만 심사 통과)

## 결제·심사

- 토스페이먼츠 심사 승인 후: 운영 `.env`에 라이브 키, `CARD_PAYMENT_ENABLED=true`, 라이브 웹훅 등록, 1,000원 실결제·취소 검증
- 구매안전서비스(에스크로) 가입처를 `apps/web/src/lib/company.ts`의 `escrow`에 넣기 (하단·주문서에 자동 표시)
- 실제 판매 상품 등록, "테스트 상품" 판매 중지 (심사 반려 사유)

## 사용자 확인 필요

- 약관·개인정보처리방침 초안 검토 (`apps/web/src/app/terms`, `privacy`, `policy`)
- 임의로 정한 운영 값 확인: 고객센터 평일 10~18시, 출고 1~3영업일, 제주·도서산간 추가 배송비, 교환은 반품 후 재주문, 무통장 입금 기한 48시간, 기한 임박 알림 6시간 전
- 테스트 서버에서 무통장 흐름 전체 확인: 주문 → 메일 2통 → 입금 확인 → 환불 계좌 입력 → 취소 → 송금 완료

## 운영 준비

- 운영 서버를 따로 둘지(지금 Vultr를 운영으로 쓸지) 결정, 정식 도메인 구매·연결
- (선택) 상품 엑셀 일괄 등록
